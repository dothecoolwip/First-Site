# BUHURT: Steel & Tape — handover for the next assistant

You are picking up a browser game called **BUHURT: Steel & Tape**, a free single-file web game about buhurt (armoured medieval combat, Canadian prairie clubs). This document is the complete brief: what it is, what's built, where everything lives, how to build/test/ship, and what's still open. Read all of it before touching anything.

## 1. What the game is

- A 3D game (three.js r149) that runs in the browser on phone, tablet and PC, installable as a PWA. One `index.html` (about 16.5 MB, everything inlined: models as base64, sounds, scripts).
- Setting: a **real-life medieval festival** with people in costume. **No monsters, dragons or magic gameplay.** Weapon "skins" are cosmetic only. Halloween ghosts/graveyard decoration are fine.
- Core loop: you walk a big open "realm" (festival fairground + five districts), talk to vendors, gather materials, and fight bots or friends in 1v1 to 12v12 buhurt matches with real buhurt rules (down = out, cards, rounds).
- Live at **https://buhurt-steel-and-tape.vercel.app** (Vercel project `buhurt-steel-and-tape`, team id `team_48w65sgEoANAtsp7G3WioNnz`), deployed from the GitHub repo **dothecoolwip/First-Site** branch `main` (the repo holds the built `index.html`, `sw.js`, `manifest.webmanifest`, icons, `admin.html`, `PLAN-realm.md`, this file).
- The game is tied to **BuhurtOS** (a separate buhurt-league web app by the same owner) through its Supabase project `mvbxlebznlgroptwwdsm` (publishable key `sb_publishable_u76M-dggKSsdsyhUQKveJg_5fPJ5Nan`, URL `https://mvbxlebznlgroptwwdsm.supabase.co`). ## 3. Backend (BuhurtOS Supabase project `mvbxlebznlgroptwwdsm`)

Tables added for the game (all other tables belong to BuhurtOS; **do not alter them**):
- `public.steeltape_throne (seat pk, holder_name, holder_uid, holder_fighter, since, challenges, updated_at)` — two rows `king`, `queen`. RLS: public read.
- `public.steeltape_events (id, kind, uid, name, data jsonb, ua, at)` — kinds `session`, `match`, `bug`, `feature`, `throne`. RLS enabled, no public policies (service role only).

Edge functions (all deployed with `verify_jwt=false`, CORS open, use service role inside):
- `steeltape-roster` GET → `{ teams[{slug,name,colors,initial}], fighters[{id,name,team,g}], live[] }`. Only approved teams, active fighters, skips fighters whose `cards.game_use=false`. `live` = open lyst fields (`lyst_field_current` → `matches` → `entries`/`entry_fighters` → `match_live_scores`).
- `steeltape-throne` GET → seats; POST `{seat, action:'challenge'|'claim', name}` (+ optional Bearer BuhurtOS JWT). First challenge of a seat → `{bow:true}` and the seat transfers; later → `{bow:false, holder}`. `claim` transfers after a win (client-trusted).
- `steeltape-event` POST `{kind, name, data}` (+ optional Bearer) → inserts an event.
- `steeltape-admin` GET/POST with Bearer; only emails in `ADMIN = ['garrettrobson95@gmail.com']`. Returns 30-day players, sessions/matches per day, modes, reports, throne. POST `{action:'resolve', id}` toggles a report done.
- `steeltape-discord` POST with `x-dispatch-secret` → posts patch notes (from its bundled `notes.ts`) into the BuhurtOS Discord `#patch-notes` under the "BUHURT: Steel & Tape" category; skips notes whose first line was already posted. Trigger it from SQL: `select net.http_post(url:='https://mvbxlebznlgroptwwdsm.supabase.co/functions/v1/steeltape-discord', body:='{}'::jsonb, headers:=jsonb_build_object('Content-Type','application/json','x-dispatch-secret',(select value from private.discord_config where key='dispatch_secret')), timeout_milliseconds:=60000);` then read `net._http_response`. The full patch-note history (v1 … v3.7) is in the scratch copy of `notes.ts`; the deployed copy only needs the newest note.

`admin.html` (in the deploy repo, served at `/admin.html`) signs in with BuhurtOS (supabase-js from CDN, storageKey `steeltape-admin`) and calls `steeltape-admin`. For Google sign-in to work there, `https://buhurt-steel-and-tape.vercel.app/admin.html` must be an allowed redirect URL in the BuhurtOS Supabase Auth settings (the game's own URL already is).

## 4. Shipping

1. `python3 build.py` → lint → run the relevant Playwright specs (or the whole suite before a big ship).
2. Copy `pwa/index.html` and `pwa/sw.js` into the deploy repo, commit, push `main`.
3. Deploy: Vercel `create_deployment` with `gitSource {type:'github', org:'dothecoolwip', repo:'first-site', ref:'main', sha}` and target `production` (auto-deploy from GitHub also works if enabled).
4. Add a patch note to `notes.ts`, redeploy `steeltape-discord`, fire it from SQL (above).

## 5. What is built (as of Patch 3.7, 11 Oct 2026)

- Fights: 1v1 to 12v12, buhurt rules, rounds, cards, tape repair bench, training yard with lessons, duel ladder, Rumble tourney, daily, Gauntlet run, summer season, rival, couch split-screen, online (lobby, invites, p2p), youth mode, photo mode, replay.
- Career: levels, skill points, purse, achievements/awards, progress tracks, 12 vendors with tabbed card UIs, tiers (fairground / Outer Bailey at level 15 + Bailey writ via a duel with Sergeant Brask / King's Court at level 40 + Royal writ via 5v5 vs the King's Guard; tier-2/3 vendors take upgrade bars further; `tierCap()`).
- Trades: mining, woodcutting, foraging (timing minigame at ~90 nodes across districts), forging, smithing, artificing; everything buyable can be made from materials. Inventory: 30-slot bag (to 50 from the Land agent), equipment panel.
- The Realm (600 × 640 m): Fairground (the Dome holds the original list), Millbrook Village (SW), Old Woods (W, quarry, hermit), Mirror Lake (E, beach, boathouse), Outer Bailey and King's Court (N, castle with Great Hall). Roads + signposts, district banners, no teleporting: waypoints with fixed gold markers, road-network routing (`realmRoute`), autowalk, sprint stamina, horses (hire $40 / buy), wandering animals. Six arenas, each spectatable (rail/follow/orbit/broadcast cams), always a bout at the nearest one; arenas are venues too; Rumble final is in the Great Hall. Six hidden places giving free cosmetics. Cell-based culling + per-cell mesh merging for performance; people beyond ~65 m aren't drawn.
- Fighting 2.0: directional attacks (L2R/R2L/O; **no thrust**, it is illegal in buhurt and would break the online move encoding), **directional blocking for players and bots** (side chosen by mouse flick / right stick / drag on the guard button; wrong side or middle guard lets half through), parry → riposte, shield bash, feints, momentum, hit stun, balance meter, team peel, AI tiers by place (fairground / bailey / court). Target feel: "mediocre challenge" (~60/45/35% win rates, not measured yet).
- BuhurtOS: roster import (20 teams, ~217 fighters), bots named after real fighters with a soft club glow, the real person in a match gets a big glow + banner + crowd roar, LIVE arena mirroring real lyst fights, King and Queen seats, **made-up clubs rebranded to real teams at runtime** (`rosterRebrand()`: wardens/rabble/league/ladder/rival), player joins their real team (or "festival-goer").
- First-time flow: 5v5 test fight with only button hints → "Teach me / I've got it" → creator (BuhurtOS sign-in required → team → fighter: name, number, men's/women's, height, build, skin, charge) → skippable realm tour. Existing players get the creator next launch.
- Announcer: speech synthesis with a ranked voice pick, music ducking, cadence; voice picker in Settings → Sound.
- Feedback: "Report a bug / idea" in the pause menu and the realm map menu → `steeltape_events`; `admin.html` shows them.

Intended uses: HighLands barracks/hut/towncenter/walls/towers/windmill for the castle and village, dungeon props for the crypt/cellar hidden places and the Great Hall, ambient pack for district ambience, crowd walla, horse sounds, better sword hits. 5. **Sign-up**: the creator's "Email me a code" creates BuhurtOS accounts (`shouldCreateUser: true`). Confirm the owner is fine with game players getting BuhurtOS accounts; otherwise point them at the BuhurtOS site.
6. **Difficulty tuning**: measure real win rates with the `match` events (admin page shows per-mode win rates) and adjust `AI_TIER` in `06b_fight2.js` / `DIFF` in `01_data.js`.
7. **Performance on phones**: the page is 16.5 MB; realm draw calls ~300–1500 depending on where you stand. Ideas: lazy-load `realm_geo.js`/`animal_geo.js`, lower cull distance on touch (already 115 m), fewer folk.
8. Flaky two-tab tests (§2). Tour captions assume English. The `peasant`/`forest`/`beach`/`hall` venues reuse `buildVenueField/Castle` and could use the new packs.
9. The owner wants every step announced in Discord as a patch note (see §3/§4) and the realm plan (`PLAN-realm.md`, also saved in the claude.ai project as `claude/realm-plan.md`) kept current.

## 7. Conventions the owner cares about

- Plain, friendly in-game copy; vendors have personalities; buhurt rule references (BR/REG numbers) are real.
- No teleporting in the realm. No thrust attack. No monsters/magic. Only display names and team colours from BuhurtOS, never private fields; fighters who opted out of the card game (`cards.game_use=false`) are excluded.
- Credit people who suggest features in the patch notes (e.g. directional blocking: @kestonpiche).
- Commit messages are descriptive one-liners; the owner reads the Discord notes, not the commits.
